## 2. Product, reference planes and presets

Fourth separate mode: `polarized_two_path`, labelled polarized two-path
interference. Sequential remains the passive startup default; loading/reloading
does not submit computation. The three existing modes keep their current APIs,
defaults, scientific policies and version-1 document exports.

New controls: grid/wavelength, supported source parameters, four real coefficient
parts, two nonnegative arm distances, zero-to-two ordered actions per arm,
unwrapped common arm-1 phase, one analyzer checkbox and one shared signed axis
angle. Simple lists support stable selection, add/delete/reorder and axis/
retardance edits. QWP/HWP buttons set retardance pi/2 or pi; they are not new
action kinds. Disabled analyzer angle remains authoritative saved input and is
still validated. Changing enablement OR angle is a scientific edit.

Use the existing numeric-binding discipline: replaying unchanged displayed text
does not shorten authoritative SI values. Angles may have degree editors but
SI radians remain authoritative; intentional edits convert once without wrapping
or snapping. Explicit simulation and explicit 17-point sweep are separate buttons.

Recommended three primary presets, all uniform amplitude1/phase0, wavelength
633nm, 64x64, dx=dy=4um, x coefficient1 and y0, phase0:

| Preset | Arm0 | Arm1 | Analyzer |
|---|---|---|---|
| Identical lossless arms | distance2mm, no actions | distance2mm, no actions | disabled, saved angle pi/4 |
| Orthogonal arms, raw | distance2mm, no actions | distance2mm, HWP axis pi/4, retardance pi | disabled, angle pi/4 |
| Orthogonal arms + common analyzers | same | same | enabled, angle pi/4 |

The HWP preserves its public complex phase and ordinary residuals; it is not
replaced with an exactly orthogonal hand vector. Analytic expectations use the
declared matched fixture and measured tolerances. Optional coefficient buttons
may reuse existing explicit x/y/diagonal/circular numeric presets; arbitrary
entered coefficients are never normalized. Asymmetric Gaussian/complex, lossy,
noncommuting and weak configurations belong to tests/probes, not extra product
frameworks or a preset library.

Schematic topology: input -> B -> two arms -> ordered terminal actions -> common
phase on arm1 -> B_dagger -> raw output pair -> optional identical analyzers.
Distances are scientific. Lane spacing, device housings and output-screen gaps
are cosmetic. There is no propagation between terminal actions or from the
drawn recombiner to screens; analyzers act at the output reference plane.
No inferred reflected-frame flip, coating law, phase or mesh-derived path length.
No arbitrary topology editor, tilted planes, material model, vector Maxwell,
quantum claim, calibrated watts or sampling guarantee.

Two 3D output screens have raw/analyzed viewing selection, with matching captions,
port IDs, request identity and picks. The ordinary result panel can show all
four returned images simultaneously for an enabled analyzer (two when disabled),
allowing a genuine raw-versus-analyzed screenshot. All images share one explicit
intensity range. Joint auto-range takes the maximum across every available raw
and analyzed image, not just the selected pair. Original Float64Array values,
maxima, saturation and small nonzeros remain authoritative. Preserve existing
half-pixel physical edges, +y-down conventions, physical aspect and sRGB display.
There are no invented spatial stripes or ellipse trajectories in this mode.

## 3. Exact proposed scientific app specification

New app model identifier (proposed, not an existing numerical export):
`v2g_ideal_polarized_two_path_v1`. Inner app `schema_version=1` is distinct
from outer settings document version2 and wire protocol version1.

Every object is closed to its listed keys, with no defaults on import:

```text
Experiment = {
  schema_version: 1,
  model_contract: "v2g_ideal_polarized_two_path_v1",
  wavelength_m: positive finite binary64,
  grid: {ny: integer1..128, nx: integer1..128, dy: positive real, dx: positive real},
  source: UniformSource | GaussianSource,
  coefficients: {x:{re:real,im:real}, y:{re:real,im:real}},
  arm_0: {distance_m: nonnegative real, actions: Action[0..2]},
  arm_1: {distance_m: nonnegative real, actions: Action[0..2]},
  relative_phase_rad: signed finite real,
  analyzer: {enabled: exact boolean, axis_angle_rad: signed finite real}
}
UniformSource = {kind:"uniform", amplitude:nonnegative real, phase_rad:real}
GaussianSource = {kind:"gaussian", amplitude:nonnegative real, phase_rad:real,
                  waist_radius_m:positive real, waist_z_m:real,
                  center_x_m:real, center_y_m:real}
Action = {id:ID,kind:"linear_polarizer",axis_angle_rad:real}
       | {id:ID,kind:"linear_retarder",axis_angle_rad:real,retardance_rad:real}
```

JSON real values accept int/float tokens excluding bool, converted once to usable
finite binary64; reject overflow and nonzero-to-zero conversion, no nonzero
rounding/snapping in the app. Canonicalize signed zero only to +0 for new-mode
browser correspondence, as explicitly documented; do not change old-mode policies.
Integer axes/schema/version require actual integers excluding bool. Reject
nonstandard constants, duplicate keys, invalid UTF-8/BOM, and nonzero decimal
underflow before request validation with the new local protocol parser. Do not
alter the old scalar request parser to impose a new policy on existing routes.

Gaussian supports the full existing public source schema, including signed
nonzero waist_z_m. Its field is sampled at source z=0 through public sample_source.
Unlike existing same-plane polarization mode, V2g does not impose waist_z=0.
No source fields are silently ignored; unknown fields reject. Public V0 source/
geometry validation remains authoritative. The only new app resource/action
restrictions are axes<=128, two actions per arm and the fixed topology/analysis.

IDs match `[A-Za-z][A-Za-z0-9_-]{0,31}`, unique across both action lists, excluding
input, splitter, combiner, arm_0, arm_1, port_0, port_1, analyzer. IDs are stable
app editing/correspondence identity, included in requests/settings/digests.
Mapping strips only the declared id/kind discriminator and passes axis/retardance
to the matching public action constructor. Public V2f actions have no IDs or z.
Preserve list order exactly; append/remove/reorder never changes another action's ID.
Readout pixel, view selection, camera and colors are presentation and not in this
scientific specification/document. Analyzer settings are scientific saved fields.

Validation constructs public SequentialExperiment for source-only sampling
(components empty, observation source_plane at0), public V2f action/arm/spec
records and app limits without sampling or constructing an incident Jones field.
It can check static domains/derived geometry; it cannot certify all derived
scalar states or promise computation. Label it "specification accepted", never
"physically validated". Existing source and V2f complete-pipeline restrictions
remain, including contextual failures, zero inputs, null ratios and unclamped
signed residuals. No changes to src/, numerical tests or mathematical contracts.

## 4. Public orchestration and atomic analyzer contract

Proposed app bindings are local to the new adapter: frozen
PolarizedTwoPathExperiment with from_dict/to_dict; immutable
ValidatedPolarizedTwoPathSubmission and ValidatedPolarizedTwoPathSweepSubmission;
validate_experiment, validate_submission(payload,require_digest=True),
validate_sweep_submission(payload,require_digest=True), simulate_submission ->
bytes and sweep_submission -> the new protocol's own SweepReply(status_code,body).
The require_digest=False path requires null and is used only by noncomputing
validation; compute paths require an exactly matching nonnull server digest.
Frontend PolarizedTwoPathAPI has validate, validateSweep, simulate and sweep;
both validation methods use the same new validate route with distinct typed
envelopes. These are bounded mode-specific adapters, not a shared API framework.

Single accepted request:

1. sample_source(source_plane) exactly once.
2. JonesField.from_scalar(scalar,x_coefficient=cx,y_coefficient=cy) exactly once.
3. Construct the phase-specific public PolarizedTwoArmSpec with public arms/actions.
4. run_polarized_two_arm(incident,spec=spec) exactly once; retain both actual raw
   Jones outputs and its public norm record during measurement/encoding.
5. If enabled, apply_linear_polarizer(raw_output,axis_angle_rad=shared_angle)
   exactly once for port0 and once for port1. No analyzer calls when disabled.
6. Obtain each raw/analyzed image from public JonesField.intensity; analyzed
   norm from sampled_norm. Public transmission_ratio(incident,analyzed) supplies
   original-input fractions; transmission_ratio(raw_output,analyzed) supplies
   separately named raw-output fractions. Copy raw norms/diagnostics from V2f.
7. Compute only scalar budget arithmetic on measured scalars: removed_norm is
   raw_norm-analyzed_norm (signed), total_norm/total_removed_norm sum both ports.
   total_original_input_ratio is the sum of the two public original-input ratios
   (null if undefined), explicitly labelled as such; do not assert a different
   association of division and reduction is bit-identical. Check finite arithmetic.
8. Encode the complete requested result once and release full field intermediates.

No new B, Jones, propagation, intensity or norm equations. No old scalar runner
substitute, source-equation copy, component deletion, normalized representative,
retarder phase compensation, phase fit or raw-output replacement. Public V2f's
runner-only128 cap and scalar/Jones intersection stay unchanged.

If V2f succeeds but either enabled analyzer, norm or ratio measurement fails,
the requested numerical outcome is FAILED: contextual422 numerical_failure for
documented numerical/domain failures, bounded500 for unexpected internal errors.
No raw-only success is published, no successful point row is appended, and V2f
is not rerun. This is distinct from a later frontend presentation failure after
a fully decoded numerical result; that result remains completedNumerical for
explicit display-only recovery. Preserve original exception cause internally.

## 5. Distinct request/result/sweep transport

New routes on the existing server only:
POST /api/v2g/validate, /api/v2g/simulate, /api/v2g/sweep.
Old routes, error roles, OHLABV1/OHLAB2P/OHLABPL formats and limits are unchanged.

Closed single/validation request keys:

```text
{protocol_version:1,message_type:"polarized_two_path_submission",
 request_id:canonical lowercase UUIDv4,experiment_sha256:null|SHA256,
 experiment:Experiment}
```

Validate requires null digest, computes no optics and returns:
`{protocol_version:1,message_type:"polarized_two_path_validation",request_id,
experiment_sha256,experiment}`. Simulate requires the digest of the owned
canonical full specification returned by validation; server independently
revalidates and recomputes identity. Digest is compact sorted ensure_ascii Python
JSON of validated SI experiment, SHA256; it is correspondence, not authenticity,
successful physics, persistence or replay qualification.

New binary magic `OHLABPT\0` (8 bytes); preamble `<8sII` is 16 bytes: magic,
unpadded JSON-header byte count, reserved zero. Compact ensure_ascii finite JSON,
zero padding to8-byte alignment; encoded header plus padding <=16,384 bytes.
No trailing/overlapping/gapped payload, unknown roles or nonzero padding.

Exact header keys:

```text
protocol_version:1, message_type:"polarized_two_path_result", request_id,
experiment_sha256, experiment, norms, diagnostics, analysis, arrays, intensity_max
```

`norms` has exactly public six pairs inputs/split/propagated/elements/combiner/
outputs and arm_action_norms (ordered two histories, length0..2 matching actions).
`diagnostics` has exactly public properties:
inputs_total,split_total,propagated_total,elements_total,combiner_total,outputs_total;
split_delta,propagation_delta,elements_delta,phase_delta,recombination_delta,total_delta;
propagation_deltas,element_deltas,phase_deltas; arm_action_deltas;
output_fractions,total_output_ratio. Copy from public record; no image integration.

`analysis` always has exactly enabled,axis_angle_rad,ports,total_norm,
total_removed_norm,total_original_input_ratio. When disabled: false plus saved
angle; ports and all three totals are explicitly null. When enabled: true,
matching submitted angle; ports is ordered pair of records with exactly
id,raw_norm,analyzed_norm,removed_norm,original_input_ratio,raw_output_ratio.
IDs are port_0/port_1; norms are public measurements, losses signed, ratios
finite/nonnegative or null according to their actual denominators. Do not
substitute zeros/raw arrays for absent analyzed data or clamp ratios above1.

Each array descriptor has exactly name,role,port_id,state,dtype,order,shape,
offset_bytes,nbytes,units. dtype="float64-le", order="C". Images are shape[ny,nx],
units amplitude_unit^2; shared x/y are [nx]/[ny], units m and null port/state.
Inventory/order:

| Enabled analyzer | Ordered payload |
|---|---|
| false | raw_port_0_intensity, raw_port_1_intensity, x_m, y_m |
| true | raw_port_0_intensity, raw_port_1_intensity, analyzed_port_0_intensity, analyzed_port_1_intensity, x_m, y_m |

Image role="intensity", state="raw" or "analyzed", matching port ID;
axis role="coordinate". intensity_max is ordered2 or4 actual image maxima,
matching this inventory. Shared physical axes describe one common output grid.
No complete complex Jones arrays, intermediate full fields or trajectories.

Exact maximum payload P=8*(k*nx*ny+nx+ny), k2 or4. At128x128:

| Analysis | Payload P | Preamble | Padded header cap H | Complete frame cap F |
|---|---:|---:|---:|---:|
| disabled |264192|16|16384|280592|
| enabled |526336|16|16384|542736|

Request cap32,768 bytes. Overall bounded result read542,736 bytes; after header
validation enforce the enabled/disabled exact inventory and smaller applicable
bound. New single result never uses the old two-image cap. Use explicit LE
DataView decoding, owned Float64Arrays, finite nonnegative images, finite axes,
strict enum/schema/count/offset/maxima checks and exact request/specification/
digest matching before publication. Preserve original binary64 values and reject
wrong magic/version, stale/cross-mode responses, swapped roles and malformed
bounded headers. Same-reduction serialization chains may be exact; analytic
equivalence uses explicit tolerances, never bit equality across associations.

New sweep request keys:

```text
{protocol_version:1,message_type:"polarized_two_path_sweep_submission",request_id,
 fixed_experiment_sha256:null|SHA256,fixed_experiment:FixedExperiment,phases_rad:17values}
```

FixedExperiment is exactly Experiment without relative_phase_rad; all source,
coefficient, arm/action and analyzer fields remain. Validate a sweep envelope
with null fixed digest at /api/v2g/validate. Its distinct reply has exactly
protocol_version:1,message_type:"polarized_two_path_sweep_validation",request_id,
fixed_experiment_sha256,fixed_experiment,phases_rad,sweep_sha256. Actual /sweep
requires the nonnull fixed digest and exact phase list; server recomputes both
digests. This validation performs zero optics. The frontend freezes the current
valid draft and marks pendingSweepValidation to reject duplicate intent before
this exchange; recheck revision/attachment epoch and acquire the existing client
compute gate immediately before the actual sweep request. A changed draft or
busy gate rejects that intent, with no queue or automatic retry.

phases_rad are the existing explicit17 values k*pi/8,k0..16, stored as canonical
binary64 constants including independent0 and2*pi. Sample/construct incident
once, construct public phase spec per point, call V2f once and analyzers0/2 per
point. Never run separate raw/analyzed sweeps. Discard full point fields after
their scalar row. No trigonometric substitution/cache/end-point duplication.

Closed sweep response keys:
protocol_version,message_type="polarized_two_path_sweep",request_id,
fixed_experiment_sha256,sweep_sha256,fixed_experiment,phases_rad,status,
requested_count,completed_count,failed_index,rows,error.
Each row has exactly index,phase_rad,norms,diagnostics,analysis, using the same
bounded scalar definitions; no arrays/maxima/images/sample trajectories.
Sweep hash covers fixed_experiment and actual phases. Maximum response65,536
UTF-8 bytes; at most17 genuine scalar rows.

Complete: HTTP200,status complete, requested/completed17, failed_index/error null.
Failed point: HTTP422 numerical_failure or500 sweep_failed, status failed,

0..completed_count-1; error exactly{code,message}, at most300 Unicode scalars.
Source/incident failure means failed_index0 and empty rows. Analyzer failure at
pointk does not append its raw-only row. Encoding failure is a bounded generic
500 operation error, never fabricated point rows or successful-looking partial
data. A failed sweep may show a clearly labelled prefix but is never complete.
Selecting a completed marker performs zero computation; a separate explicit
"use phase and simulate" action edits phase, validates and makes one full-array
submission under a fresh UUID. Do not auto-submit on marker selection.

Typed operation errors use distinct polarized_two_path_error with
protocol_version,request_id,error{code,message}; generic body/boundary failures
