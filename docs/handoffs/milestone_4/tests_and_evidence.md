## Evidence interpretation

Independent tests use hand-calculable identities and scalar/80-digit Decimal
references constructed from the exact stored binary inputs. Expected arrays
or scores are not generated by another production metric call. M3 integration
uses the actual unmodified reconstruction, separately rebuilds the returned
source phase through public ASM, and preserves all input/result bytes.

The seven negative controls below intentionally introduce specific incorrect
calculations. An assertion failure is the required detection; import,
collection or setup failures do not count. This is finite demonstrated coverage,
not a claim that every possible defect is detectable.


## Independent shipped-function measurements

This measurement calls the implemented public metrics, not the earlier planning
expressions. Its independent references use 80-digit Decimal arithmetic built
from each exact stored float through `Decimal.from_float`. The fixed 2-by-2
arrays are evaluated at intensity scales `1e-6`, `1` and `1e6`; the same
explicit first-row ROI is used for fraction and CV. PSNR range is scaled
consistently as `1.5*scale`. No production helper computes a reference.

| Metric | Maximum absolute error | Maximum relative error | Explicit rtol | Explicit atol |
|---|---:|---:|---:|---:|
| Intensity MSE | 1.1102230246251566e-17 | 6.044512703811923e-17 | 5e-15 | 0 |
| Target-normalized intensity NMSE | 7.553312201723288e-17 | 8.243820220164408e-17 | 5e-15 | 0 |
| Intensity PSNR | 8.161333069578308e-15 dB | 1.1176422218971367e-15 | 0 | 1e-12 dB |
| Signal-region power fraction | 7.174910703359855e-18 | 4.585703797364777e-17 | 5e-15 | 0 |
| Regional population CV | 4.4492869795942e-17 | 1.461908579009523e-16 | 5e-15 | 0 |

These finite-case measurements support the stated comparison bounds; they are
not universal float64 error bounds. The relative-only bounds accommodate the
few-epsilon errors measured for nonzero scalar references across these scales,
without an absolute floor that could hide a small nonzero metric. PSNR uses an
absolute dB bound because subtracting logarithms can lose relative precision
near zero dB. Its measured absolute error remains well below that bound.

The additional large/small-range cases return 4000, -4000 and 4000 dB, while
avoiding a range square or quotient that would overflow or underflow. Their
Decimal-reference absolute errors are at most 2.628947601509371e-16 dB. The
reference uses the actual stored range and intensity values, so those printed
integer scores are not claimed to equal the exact real-valued scores without
roundoff. Nonidentical inputs still require usable squared-error arithmetic.

The separately labelled exact-zero cases have zero absolute error; relative
error is undefined at a zero reference and is explicitly reported as null.
The full-window fraction is exactly one after denominator validation, and
signed-zero numerical equality gives positive-infinite PSNR. These checks
exercise stated exact contracts, not approximate comparisons.

## Small actual-M3 integration and demo reference comparison

The integration fixture is defined in `tests/test_metrics.py`. Expected scores
use scalar intensities from public ASM applied to the independently rebuilt
returned phase, then Decimal references rounded to float64 for comparison.
This includes reconstruction roundoff, unlike the preceding true-Decimal
comparison of metrics on identical stored input arrays. Maximum scalar relative
difference in this integration was 3.8875820463163017e-16; PSNR differed by
1.7763568394002505e-15 dB. The complex-field comparison uses M3's measured
`rtol=1e-12, atol=1e-13*source_peak`; intensity and amplitude-residual
comparisons use `rtol=1e-12, atol=1e-14`. Metric scores use the tighter
`rtol=5e-15, atol=0` (PSNR `rtol=0, atol=1e-12 dB`).

The demo comparison evaluates the exact unchanged planning fixture through the
shipped functions and independent scalar `math.fsum` reductions. Only three
scores differ by one ULP: twice-target MSE/PSNR and actual-GS NMSE. The cause
is reduction-order rounding propagated through division/logarithms, not changed
parameters, targets, reconstruction or formulas. Rounded planning-table values
are not an exact-match acceptance target.

## Seven isolated negative controls

Each mutation is compiled into a fresh process's `ohlab.metrics` namespace;
no source file is written. The driver requires exactly one assertion failure
from its independently specified test, zero other call failures and zero
collection/setup/teardown failures. The amplitude-confusion mutation replaces
the intensity-error numerator with square-root differences while retaining the
intensity denominator, deliberately testing an inconsistent-domain defect.

| Mutation | Independent expected assertion | Observed wrong result |
|---|---|---|
| Amplitude/intensity confusion | Twice-target NMSE = 1 | 0.22876383367174655 |
| Independent peak normalization | Twice-target MSE = 5/16 | 0 |
| Reconstruction-inferred range | PSNR with range 1 = 5.05149978319906 dB | 11.072099696478684 dB |
| ROI as its own denominator | Fraction = 3/8 | 1 |
| Ignored mask | One-pixel fraction = 1/16 | 1 |
| Inverted mask | Fraction = 3/8 | 5/8 |
| Sample ddof=1 | Population CV = 2/3 | 0.9428090415820635 |

All seven were detected. All 29 numerical-source/test Python file hashes were
unchanged after the isolated processes. Exact transcript follows; elapsed
times and memory addresses in pytest failure displays are run-specific and
